16 cells, 59c DDDSUUDDDD, F08_CG1 loopback, no nsys, one binary for every mode (dapp_hook yaml: enable / async_export).
Scripts: fullstack/fullstack_run.sh (hook modes off | full | async), async_runs.sh, async_runs2.sh, cpu_report.py,
ring_compare.py. Statistics exclude the first second. Drop line: L2A end - tick > 600 us (check_time_threshold).

Change: with async_export: 1 the L2A msg_processing thread (core 12) queues one descriptor per TTI request and per
SLOT_END; the dapp_export thread (core 43, SCHED_FIFO 90, polling) walks the message and writes the same records.
The request's nvIPC buffer is released by the msg_processing thread once the export thread has passed it.
CPU assignment before/after: core 43 was unused (isolated); now dapp_export, 100 % busy by polling. Nothing else moved.

Remaining risks / notes
 - The export thread needs its own isolated core (43 here) and polls at 100 %.
 - A message is not exported when the queue (1024) or the held budget (256) is full; never observed (max depth 2).
   The counter is only on the console line, not in the ring header (ABI untouched).
 - Residual L2A cost is +2.5 us per slot at 16 cells (16-17 descriptors); it scales with the number of TTI requests,
   not with the number of PDUs.
 - Record ts_ns now is the hook time for every record of a message (inline: each record's own write time, ~100 ns
   apart); the write itself is 0.8 us later.
 - Start-up behaviour is unchanged: the first UL/DL slot is dropped by NVIDIA's warm-up branch in every mode.
