Q2. 16셀 루프백의 TDD 패턴 — DDDSUUDDDD. 16셀 DSUUU 패턴·TV는 없다
- 실제 로드되는 파일은 testVectors/multi-cell/launch_pattern_F08_16C_59c.yaml (testMAC은 multi-cell/에서만 읽음 common_utils.hpp:34, main.cpp:320-322; RU 에뮬레이터 config_parser.hpp:175;
  run3_mig16.log:11,16으로 확인). 루트의 testVectors/launch_pattern_F08_16C_59c.yaml(재구성본)은 쓰이지 않음(stride 40인데 생성기 make_launch_pattern_4t4r.py:57은 20 가정 → 다른 셀 TV를 집음).
- 80슬롯, 매 10슬롯 D D D S U U D D D D. UL(UL_TTI) 16/80: x4 = PUSCH 6UE + PUCCH(ULMIX_4471+c / 4551+c), x5 = + PRACH(4511+c / 4591+c). DL 64/80 (S슬롯 x3도 PDSCH/PDCCH, UL 없음).
  UL TV는 slot 0으로 생성된 것을 4/5/14/15에 놓은 것 → static*SlotNum: 0 덕에 동작.
- testVectors/multi-cell의 launch_pattern_F08_* 1752개(패턴 39~85)는 전부 DDDSUUDDDD 또는 DDDXUUDDDD/DDDXXXDDDD 변형. UL 최대 2~3/10. DSUUU·DDSUU 없음.

  미검증: UL 슬롯 3배(6/10)의 GPU 여유와 testMAC UL 인디케이션 창(8슬롯), S슬롯(PDSCH만) 처리.

결론
- "한 L1에 실 셀 1 + 에뮬 15셀"은 설정상 표현 가능하지만 L2A의 전역 static 슬롯 오버라이드 때문에 두 종류 셀이 동시에 정상일 수 없다. 선택지:
  (a) static -1(실 셀 정상): 에뮬 셀은 CRC 실패·RU DL 검증 오류를 내며 "부하만" 제공(GPU 부하는 거의 같음: LDPC 고정 반복) → 부하원으로는 쓸 수 있으나 에뮬 셀의 KPI는 의미 없음.
  (b) 에뮬 셀 UL/DL TV를 슬롯별로 재생성(MATLAB) → 정석이지만 비용 큼.
  (c) 실 셀 L1(1셀, OAI)을 그대로 두고 16셀급 GPU 부하는 cubb_gpu_test_bench를 같은 MPS 데몬의 클라이언트로 함께 돌려 공급 → FAPI는 실 셀 것만 훅에 보임(부하 regime은 벤치 패턴으로 알려짐).
     E2E의 "MIG 4g 벌점"과 "세입자-RAN SM 공유"는 재현되나 "FAPI로 16셀 부하를 본다"는 부분은 1셀분만 성립.
- 16셀 DSUUU 루프백은 패턴 생성기 수정으로 만들 수 있으나 UL 3배 부하의 GPU 여유·testMAC 창은 별도 확인 필요.
